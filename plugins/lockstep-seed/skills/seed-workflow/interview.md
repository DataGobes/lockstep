# Seeding interview

Follow the rounds in Lockstep's [grilling.md](../../../lockstep-core/skills/spec/grilling.md): facts are yours,
decisions are theirs; one numbered message per round; a recommended answer for each question; "yes to all" accepted.
Skip any question the repo already answers. Round one is usually all you need.

## Round one

1. **Failures seen.** "Which agent mistakes have you had to fix more than once?" Offer the catalogue's `failures`
   phrases for the practices the plan lists as *not yet*, as a menu. Recommended: none, if they can't name one.
2. **Production.** Only if the probe found a deploy tool: "Can anyone run a production deploy from a laptop?"
   Recommended: yes, unless they show you it is pipeline-only.
3. **Personal data.** "Does this repo read or hold personal data?" Recommended: the answer the code suggests.
4. **Commands.** Only where the probe found none or several: "How do you run the tests / lint / build?"
5. **Decline.** For each practice the plan selects: "Keep `<id>`?" Recommended: yes for `risk`, the person's call for
   the rest.

Ask about team size, tracker and ceremonies only if a practice in the catalogue would change on the answer.

## answers.toml

```toml
pii = false
prod_reachable = true

[[evidence]]
practice = "glossary"
failure = "Agent read 'active customer' as any login; fixed twice in October"

[[decline]]
practice = "protect-secrets"
reason = "Samples folder is synthetic data, generated by a script"
```

A failure needs who saw it and roughly when, in the person's words, with no customer data or names.
